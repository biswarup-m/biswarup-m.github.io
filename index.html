Technical case study
Model choice
5+ VLMs benchmarked as frozen embedding extractors with 15 classifiers. The Qwen3-VL vision path gave the best balance of speed and recall.
Export
Standard tooling exports these models only as text generators, so I built OpenVINO embedding graphs for 4 architectures, each matched to PyTorch (cosine 1.000).
Quantisation
INT8 adopted where accuracy held. For Qwen3-VL it raised missed thefts from 1 to 9, so FP16 was kept; a centred-cosine check flagged this before the accuracy run.
Evaluation
Recording-level splits and nested cross-validation, so every score reflects recordings the model never saw.
Split inference
MiniCPM-V-4.5 encoded locally and decoded on a second machine from token embeddings only: burst capacity 12 → 19 clips within a 30 s deadline.
Zero-shot alerts
Conformal thresholds on text-matched scores: zero false alerts on held-out normal footage, with half of the theft recordings flagged.

Research, LaBRI, Université de Bordeaux · 2025–2026

Sparse-view reconstruction with Gaussian Splatting

Reconstructing a CT cross-section from 20 projections instead of the usual 1,000+, by optimising a set of 2D Gaussians through a differentiable projector.

  • Built the Gaussian Splatting pipeline from scratch: GPU projector with custom autograd, adaptive density control (clone, split, prune), TV regularisation and per-parameter learning-rate schedules, refined over 12 versions.
  • Added uncertainty-guided initialisation: a network predicts per-pixel uncertainty that decides where Gaussians start, adapting to each acquisition geometry with no manual tuning.
  • 20projection views instead of 1,000+
  • 27.9 dBPSNR from 20 views on a real scan never seen in training
  • +8.3 dBover standard initialisation in the limited-angle case

Technical notes
Density control
From iteration 500, every 100 steps: the top 5% of Gaussians by positional gradient are cloned or split by scale, faint ones pruned, population capped at 12,000.
Training stability
With uncertainty-guided starting positions, optimisation recovers after densification restructures the population; standard initialisation settles in a much worse solution.
Uncertainty
An evidential head predicts epistemic and aleatoric uncertainty in one forward pass. A simple ratio from that map predicted, before reconstruction, which geometries would benefit.
Regularisation
Geometry-specific TV weights chosen by sweep, adding 0.2–0.4 dB.
Next
3D Gaussians, physics-informed uncertainty and uncertainty-driven choice of the next view to acquire.

IEEE ICIP 2026 Grand Challenge · Top 5

Urban object re-identification across camera views

Matching the same street object, such as a bin or container, between a vehicle's forward- and backward-facing cameras, where viewpoint and appearance change completely.

  • Treated the camera change as a domain-adaptation problem: a domain-adversarial camera branch with gradient reversal, plus camera-balanced batches, so features describe the object rather than the camera.
  • Scaled a Part-Aware Transformer from ViT-B/16 to ViT-L/16 with external data (19.9K images) on a single 11 GB GPU, then added camera-aware re-ranking (CA-Jaccard) and checkpoint ensembling.
  • Top 5IEEE ICIP 2026 Grand Challenge
  • +72%mAP over the PAT baseline (0.102 → 0.175)
  • 19.9Ktraining images, one 11 GB GPU

Reliability under domain shift · 7 experiments

Knowing when a spacecraft pose estimate is wrong

An autonomously docking spacecraft needs more than a pose estimate: it needs to know how far to trust it. I tested whether the perception stage can flag its own errors at runtime, without ground truth, from classical features to DINOv2, through an EKF and a flight-processor budget.

  • ≈2×lower error with frozen DINOv2 than ResNet-18 on real imagery
  • 8.88 → 3.07EKF consistency (NEES) after correcting a measurement bias

Key finding: common confidence signals, including Monte Carlo dropout, stay confident exactly where error grows across the synthetic-to-real gap, so runtime checks must be validated on real imagery.

GPU pre-association for large-scale tracking

Matching thousands of detections to tracks in real time is limited by optimal Hungarian assignment, which scales as O(N³). I used GPU DBSCAN (RAPIDS cuML) to split one large assignment into many small local ones, and measured where it pays off from 500 to 10,000 detections.

  • 5.8×faster at 10,000 detections
  • ≈4,000detections: break-even point

MiniCPM-V-4.5 3D-Resampler temporal grouping in OpenVINO

Pull request #1962

MiniCPM-V-4.5 compresses groups of consecutive video frames into one shared set of 64 tokens. The OpenVINO path produced a group per frame instead, so the model received a different input layout from the one it was trained on.

The fix folds the grouping in on the host side with no change to the exported graph: already-exported models work as they are, image inputs stay bit-identical, and output matches the reference implementation (cosine 1.000000).
